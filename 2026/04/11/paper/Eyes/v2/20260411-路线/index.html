路线

发表于2026-04-11|更新于2026-07-06|论文实验
|总字数:1.4k|阅读时长:6分钟

这是一个非常聪明且极其严谨的工程策略！在深度学习开发中，这种“先搭骨架，再逐个外挂模块”的方法被称为增量式开发（Incremental Development）。它不仅能最大程度避免代码跑通后却不知道哪里出错的尴尬，还能顺手把你论文里最核心的消融实验（Ablation Study）给做了。

为了让 Codex（或 Copilot/Cursor）写出最符合你心意的 PyTorch 代码，我为你准备了英文 Prompt 序列（因为 AI 编程助手对英文指令和 PyTorch API 的映射最为精准）。

你可以新建一个工程，然后按顺序把下面的 Prompt 喂给 Codex。

第一步：搭建 Baseline（最基础的 Retinex 级联网络）

目标： 先不要任何先验（没有 SIPG）和动态路由（没有 Cond-SVIC），只用一个普通的 3x3 卷积块作为光照估计器，并实现 SCM 的 $T$ 次循环。这个版本将作为你论文里最底层的 Baseline。

新建文件：models/baseline.py

喂给 Codex 的 Prompt：

Plaintext

阶段测试： 跑通这个网络，用普通的 MSE 和 Smoothness Loss 训练。你会发现它能去噪，但会把血管抹平（这正是你论文要攻击的痛点）。

第二步：外挂先验生成模块 (SIPG)

目标： 独立实现 Student 提取网络，让它能输出你需要的张量。这一步先不和主网络连通，先保证它能跑通并输出正确维度的 $\boldsymbol{A}$。

新建文件：models/prior_net.py

喂给 Codex 的 Prompt：

Plaintext

阶段测试： 给它随机张量，打印输出维度是否为 (B, 1, H, W)。

第三步：核心替换 —— 实现 Cond-SVIC 算子

目标： 这是整个网络最复杂的地方。我们要把第一步的 BasicConvBlock 替换成带有 SPADE 和多分支路由的 CondSVIC。

新建文件：models/svic_net.py

喂给 Codex 的 Prompt：

Plaintext

阶段测试： 极其重要！传入随机张量，用 nvidia-smi 观察显存。这段代码如果写得好，显存占用应该和普通卷积几乎一样。

第四步：组装完全体网络 (Ultimate SCR-IG)

目标： 把 SIPG 和 Cond-SVIC 组装到 SCM 循环中，完成前向传播。

新建文件：models/main_model.py

第五步：手撕复杂 Loss 函数 ($\mathcal{L}_{IMS\_v2}$)

目标： 让 Codex 帮你把带重要性截断的平滑损失写出来。

新建文件：utils/loss.py

喂给 Codex 的 Prompt：

Plaintext

💡 Codex 交互小贴士：

  1. 单文件单生成： 不要把上面的 Prompt 一次性全发给它。每次只让它生成一个 Class，你自己 Review 一遍维度，没问题了再进行下一步。
  2. 要求它写注释： 你可以在 Prompt 结尾加上 Please add detailed inline comments explaining the tensor shapes at each step.，这能极大地帮你检查它的逻辑对不对。

按这个顺序，你可以优雅地拿到：Baseline → +SIPG 先验网络 → +CondSVIC 动态路由网络 → +复合 Loss 的完全体网络。每加一步，你就可以跑一个消融实验，这正是顶会审稿人最喜欢看到的开发过程。开始 Coding 吧！
