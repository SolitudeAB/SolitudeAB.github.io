3. 一句话总结

3DGS 用大量带有位置、颜色、透明度、尺度和方向的三维 Gaussian 来表示真实场景，在多视角图像和相机位姿的约束下优化这些 Gaussian，并通过快速 splatting 渲染实现高质量、实时的新视角合成。

4. 这篇论文解决什么问题

在读论文之前，我对三维重建的理解比较粗糙：我以为“视频转三维”就是生成一个 mesh 模型。

读完后发现，3DGS 关心的核心并不是生成一个传统 mesh，而是：

如何把一个真实场景表示成一种可以快速渲染的新型三维表示。

我理解它解决的是这几个问题：

  1. NeRF 渲染慢
    NeRF 需要沿每条射线采样，再查询神经网络，计算量大。

  2. 传统点云渲染效果不够好
    普通点云只是离散点，缺少连续外观，不容易生成自然图像。

  3. Mesh 从视频中重建干净表面比较难
    对真实视频，生成干净、可编辑的 mesh 并不容易。

  4. 需要一种既真实又快的场景表示
    3DGS 选择用显式 Gaussian 表示场景，兼顾渲染速度和视觉效果。

7.2 Adaptive Density Control

我理解它解决的是：

场景哪里需要更多 Gaussian，哪里需要删掉没用的 Gaussian。

如果某些区域细节复杂，只靠少量 Gaussian 表示不够，就需要 clone / split 增加表达能力。

如果某些 Gaussian 没贡献或不稳定，就需要删除。

对复现的意义是：
训练过程中 Gaussian 数量不是固定的，模型会根据重建误差进行密度调整。

7.3 Tile-based Differentiable Rasterizer

这部分我还没有完全理解底层实现，但目前的直观理解是：

它让 Gaussian 投影到屏幕并快速合成图像，而且这个过程可以反向传播。

也就是说，3DGS 能一边渲染，一边根据渲染误差优化 Gaussian 参数。

9. 和我复现实验的关系

我的自采视频实验其实就是把论文方法工程化跑了一遍：

实验步骤 对应论文理解
手机视频抽帧 构造多视角图像输入
COLMAP 提供相机位姿和初始稀疏点云
train.py 优化 Gaussian 参数
point_cloud.ply 保存训练后的 Gaussian 场景
render.py / viewer 新视角渲染和交互查看

我实验中 COLMAP 注册了 100 / 100 张图像，说明相机位姿估计比较稳定。
这也让我理解到：3DGS 复现的关键不只是 train.py，而是前面的数据质量和 COLMAP 结果。

10. 我目前读懂的地方

我现在比较清楚的点：

  • 3DGS 是一种三维场景表示，不是传统 mesh
  • 它输入多视角图像和相机位姿
  • COLMAP 在复现中通常用于生成相机参数和稀疏点云
  • point_cloud.ply 是训练后的 Gaussian 场景参数文件
  • viewer 展示的是 Gaussian splatting 渲染结果，不是普通点云预览
  • 3DGS 适合做入门复现，因为结果直观、工程链路完整

11. 我还没完全懂的地方

目前还不太懂的地方：

  1. 各向异性协方差具体怎么参数化
  2. 球谐系数如何表达视角相关颜色
  3. Tile-based rasterizer 的 CUDA 实现细节
  4. Adaptive Density Control 中 clone / split 的具体判断条件
  5. 训练中不同 loss 对最终效果的影响
  6. 为什么某些区域会出现漂浮 Gaussian 或局部模糊

这些可以作为后续继续读代码和论文的重点。

12. 论文给我的启发

读完这篇论文后，我意识到：

视频转三维不一定等于生成传统三角网格模型，很多时候更重要的是找到一种适合渲染、展示和优化的场景表示。

3DGS 的意义在于：
它把真实场景用一种显式 Gaussian 表示出来，让新视角渲染变得更快、更直观。

这也解释了为什么老师给的视频中会提到“高斯点泼溅”：
它非常适合把普通视频或多视角照片转成可以自由视角浏览的三维场景。
